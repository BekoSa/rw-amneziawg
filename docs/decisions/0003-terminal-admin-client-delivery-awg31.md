# ADR 0003: терминальное управление, AWG для всех клиентов, AmneziaWG 3.1, установщик

Статус: принято (решение владельца продукта, 2026-09).

## Контекст

- Владелец управляет пользователями только в основной панели Remnawave и не хочет дополнительной
  веб-панели, доступной из интернета.
- Модификация Remnawave Node или панели рассмотрена и отклонена: все приложения Remnawave остаются stock.
- Прежний реестр отдавал AWG только двум точным версиям клиентов (Mihomo 1.19.30, Throne 1.1.5).
- Актуальная версия протокола — AmneziaWG 3.1 (amneziawg-go v3.1.20260828; pinned runtime уже её).

## Решения

1. **TUI вместо web-ui.** Textual-приложение в контейнере во внутренней сети расширения, только
   Controller API; порты не публикуются. `apps/web-ui` удалён.
2. **AWG получают все клиенты, в собственном формате.** Реестр (`packages/capabilities`) описывает
   семейства клиентов, а не версии: Mihomo-семейство, Throne, INCY, AmneziaVPN (`vpn://`), прочие
   URI-клиенты (`amneziawg://`). Форматы, которые нельзя безопасно дополнить (sing-box JSON,
   legacy Clash), и Happ (нет поддержки AWG по документации) остаются байт в байт stock.
   Каждый формат сверен с исходниками/документацией актуальных версий (см. [subscriptions](../subscriptions.md)).
3. **AWG 3.1 как версия профиля.** Adapter `amneziawg-go-v3` принимает `1.0`, `2`, `3.1`; поля 3.1
   разрешены только в профиле 3.1. Клиент получает 3.1 только если его поддержка подтверждена (INCY — нет).
   Новые профили в TUI по умолчанию 3.1.
4. **Установщик интегрируется со stock через конфигурацию.** Единственные внешние изменения — строка
   `REMNAWAVE_PANEL_URL` в `.env` stock subscription-page и (опционально) `WEBHOOK_*` в `.env` панели;
   оба с бэкапом и откатом в `uninstall.sh`. Для этого Gateway умеет пропускать фиксированный список
   read-only маршрутов subscription-page и доверять `X-Forwarded-*` только в сети панели.
5. **Ноды подключаются ключом**, как Remnawave Node по `SECRET_KEY`: TUI выпускает сертификат ноды
   (CA расширения), `install-node.sh` его принимает.

## Последствия

- Список клиентов и их AWG-версий надо пересматривать при их релизах (golden-тесты фиксируют форматы).
- Для смешанного парка клиентов (INCY и 3.1) нужны два профиля на разных портах.
- Внутренний API subscription-page (набор маршрутов) может измениться в новых версиях; проверка
  `scripts/lab.sh installer` закреплена за `remnawave/subscription-page:8.0.0`.
