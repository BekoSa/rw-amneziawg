# Установка rw-amneziawg на работающий Remnawave

Клонировать проект не нужно: на каждый сервер скачивается **один скрипт**. Он сам берёт из GitHub
нужный compose-файл и запускает готовые образы `ghcr.io/bekosa/rw-amneziawg/*`, собранные CI.
Remnawave (панель, нода, страница подписки) остаётся стоковым.

Схема:

```
Сервер панели Remnawave                       VPN-сервер (AWG-нода)
├─ stock Remnawave + subscription-page        ├─ stock Remnawave Node (Xray), как было
└─ rw-amneziawg: Controller, Gateway, БД, TUI └─ rw-amneziawg Agent (AmneziaWG 3.1) ← ставится тут
```

## Что нужно

- Docker и Docker Compose v2 на обоих серверах.
- На сервере панели — запущенный Remnawave (установленный по официальной инструкции).
- API-токен Remnawave: **панель → Settings → API tokens → создать** (понадобится один раз).
- На VPN-сервере — `/dev/net/tun` (у большинства VPS есть; если нет — включается в панели провайдера).

## 1. Сервер панели

```sh
curl -fsSLO https://raw.githubusercontent.com/BekoSa/rw-amneziawg/main/install.sh
sudo sh install.sh
```

Скрипт спросит API-токен и задаст два вопроса:

1. **Направить страницу подписки через AWG Gateway?** — да. Меняется одна строка
   (`REMNAWAVE_PANEL_URL`) в `.env` стоковой subscription-page; прежнее значение сохраняется, `uninstall.sh`
   вернёт его обратно.
2. **Включить webhooks?** — по желанию. Без них изменения из Remnawave подхватываются раз в 15 секунд.

В конце появится команда управления **`/opt/awg-extension/awg`** (терминальный интерфейс).

> Нет стоковой subscription-page и подписки отдаёт сама панель? Установщик выведет правило для reverse
> proxy: `/api/sub/*` → `awg-gateway:8081`.

Чтобы пользователи видели ключ для AmneziaVPN на странице подписки, включите в Remnawave у конфига
страницы подписки **Show connection keys** (иначе stock скрывает все ссылки).

## 2. Выпустить ключ ноды

```sh
sudo /opt/awg-extension/awg
```

Вкладка **«Ноды»** → `n`:
- название (например `de-1`);
- адрес VPN-сервера (IP или домен) — по нему Controller будет управлять нодой;
- **«Выпустить ключ ноды»** → скопируйте ключ `awgnode1:…` (выделите мышью). Он показывается один раз.

Окно можно не закрывать — вернётесь в шаге 4.

## 3. VPN-сервер

```sh
curl -fsSLO https://raw.githubusercontent.com/BekoSa/rw-amneziawg/main/install-node.sh
sudo sh install-node.sh
```

Вставьте ключ, когда спросит (на экран не выводится). Установщик выберет **случайный свободный UDP-порт**
AmneziaWG и в конце напечатает: ID ноды, порт и команду для firewall.

Firewall VPN-сервера:
- **UDP-порт** из вывода — открыть для всех (это сам VPN);
- **TCP 8443** — только для IP сервера панели. Docker обходит UFW, поэтому так:
  ```sh
  sudo iptables -I DOCKER-USER -p tcp --dport 8443 ! -s <IP_сервера_панели> -j DROP
  ```

## 4. Подключить ноду

В TUI нажмите **«Нода установлена — подключить»**. Если окно уже закрыли: `Ноды → n`, введите название,
адрес и **ID ноды** из вывода установщика → «Подключить». Нода появится как online.

## 5. Профиль и пользователи

TUI → вкладка **«Профили»** → `n`:
- название (его увидят пользователи в подписке), нода;
- **Endpoint** — адрес VPN-сервера для клиентов; UDP-порт подставится сам;
- **Internal Squads** Remnawave, которым выдаётся AWG;
- версия **AmneziaWG 3.1** (параметры уже сгенерированы).

**Сохранить → Проверить → Применить.** Через несколько секунд нода станет READY.

Дальше всё в Remnawave: пользователь в выбранном squad получает AWG в подписке; отключение, окончание
срока, лимит трафика или удаление снимают доступ автоматически.

Проверка: `sudo /opt/awg-extension/awg peers` — пользователи, их IP, handshake и трафик.

## Обновление

Повторный запуск того же скрипта (скачайте свежий, если менялся):

```sh
sudo sh install.sh        # панель: секреты, ключи и данные сохраняются
sudo sh install-node.sh   # нода: ключ повторно не спрашивается, порт и сертификат сохраняются
```

Новые версии ядра AmneziaWG приходят через CI (еженедельная проверка и PR в репозитории); после мёржа
достаточно перезапустить `install-node.sh` на нодах.

## Удаление

```sh
sudo /opt/awg-extension/uninstall.sh           # вернуть stock-настройки, остановить; данные сохраняются
sudo /opt/awg-extension/uninstall.sh --purge   # то же и удалить БД AWG и ключи
```

Remnawave продолжит работать как до установки. На VPN-сервере:
`cd /opt/awg-node && sudo docker compose --env-file .env down` (добавьте `-v`, чтобы удалить ключ ноды).

## Параметры установщиков

| `install.sh` | |
|---|---|
| `--api-token-file FILE` | токен из файла вместо вопроса |
| `--subpage yes\|no`, `--webhook yes\|no`, `--yes` | ответы без вопросов |
| `--ref TAG` | версия файлов из GitHub (по умолчанию `main`) |
| `--image-tag TAG` | тег образов (по умолчанию `latest`, есть `sha-<коммит>`) |

| `install-node.sh` | |
|---|---|
| `--secret-file FILE` | ключ ноды из файла вместо вопроса |
| `--udp-ports 41234` или `41234-41236` | свой порт/диапазон вместо случайного |
| `--management-port 8443`, `--management-bind IP` | порт и интерфейс управления |
| `--ref`, `--image-tag` | как у `install.sh` |

Сборка образов на своём сервере вместо GHCR: `git clone` проекта и запуск `sudo ./install.sh` из него.
